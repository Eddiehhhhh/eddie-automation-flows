# Cloud weekly bundle

`scripts/cloud_weekly_bundle.py` materializes an already reviewed three-tab weekly synthesis in a clean, isolated private-vault checkout. It does not invoke a model, publish to GitHub, edit Wiki or inspect the Mac workspace. The authorized cloud task supplies private three-tab JSON outside the checkout, a fixed source commit and the actual Shanghai run date. The script audits all registered sources without the old per-source cap, writes at most the 16 approved report/index/state paths, preserves historical Observatory periods and checks its own outputs. `--verify-existing` checks a generated bundle without modifying it.

The checkout commit must equal `--source-sha`. The durable report run key is a digest of `weekly:<period>:<source SHA>:cloud`. A run key already present in weekly latest cannot be regenerated: read back its existing result. Rerunning the same week with a new source SHA keeps the original weekly Raw receipt and its existing bytes, including candidate and result entries; a new source SHA does not erase old knowledge records. A prior week cannot replace a newer weekly latest state. The caller must still compare the complete target path/blob manifest with the latest private `main`, make one commit with the exact approved paths, and push non-force only while the read parent remains the remote head. A race requires fresh target and run-key reads, never a blind retry. After publishing, read back the three tabs, receipt, indexes, frontend, state and phone-visible result. Keep the private page input and stdout out of public Actions artifacts.

The private `--pages-json` input must contain `period`, `window_end`, the three `tabs`, and explicit `wiki_candidates`, `skill_candidates`, `confirmed_facts` lists. `evidence` must name the fixed `source_snapshot_sha`, `synthesis_status` (`complete` or `partial`), a nonempty `synthesis_reference`, `semantic_review_run_id`, `registered_sources_examined`, `read_receipts` (`path` plus full-file `sha256`), and `coverage_gaps`. A `complete` claim requires a real semantic review run ID, every active registered source accounted for, full-byte receipts for every metadata-selected candidate, and no gaps. Registry entries marked `source_status=archive-only` remain visible for historical lookup but are excluded from active coverage and candidate selection. An unconfirmed personal fact shown in the personal tab must appear as a `pending_confirmation` candidate with source references. Missing proof fails closed; a partial report must list its actual gaps. The W41 historical-ledger gap is input specific and is never copied to later weeks.

Optional `knowledge_candidates` contain only `kind`, `target_path`, `proposed_text`, and `source_refs`. The script stores each distinct candidate in its original weekly Raw receipt; its identity depends on the proposed item, while `source_sha` remains separate evidence. `read_knowledge_candidates` reads archived candidate records across weeks; dot must inspect later result events and remote evidence to determine which remain unresolved. An empty later input does not delete older candidates or recorded outcomes. The report's `actual_wiki_updates` and `knowledge_results` carry forward existing results for the same week; this script never creates a knowledge success claim.

This script offers no knowledge apply or approval verifier. Raw text, a matching hash, or a caller-provided path list cannot authorize a write. Dot must read the actual authenticated user messages, prepare the complete concrete change list and cumulative impact budget, check current private GitHub versions, use the existing GitHub write tools, and read back every changed target, index, receipt, status, and display. Without those capabilities or specific approval, the candidate stays pending. A specific Skill requires its own approval and belongs under `Schema/Hermes Skills/`; personal facts and rules retain their own approval boundaries. This local bundle does not claim to produce a complete knowledge patch manifest.

Initial generation records System 4.0 as partial while remote, mobile and natural-run proof is absent. Once those are independently read back, provide `--acceptance-json` with the published commit, source SHA, run key, remote readback time, phone result URL/time and natural run ID against a clean checkout of that published commit. This second step updates only the closeout, weekly latest, System 4.0 state and auxiliary receipt. Both verification and acceptance require an existing canonical receipt under `Raw/05 Chat/` with the exact week in its filename; state fields cannot redirect them to another file or symlink. It cannot mark a source-incomplete week successful. Weekly streaks are recomputed from actual consecutive week statuses while preserving daily history and earlier weekly evidence.

The legacy `iteration_closeout.py` no longer auto-upserts Wiki from source-count heuristics. Its four-source closeout and workspace intake are not a substitute for cloud synthesis. Only Eddie-confirmed facts may enter personal Wiki through a separate version-checked transaction. A partial System 4.0 status is intentional when source or display evidence is missing.
